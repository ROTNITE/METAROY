Объём поставки и исключения

Из шести последних ZIP четыре являются уникальными патчами Mission Flow. Два Resource Predictor имеют идентичный SHA-256 2b80a5de4d0f56d5a1106932141eafa850d285191b01549e6269b18cd289ffc1. obixod-benchmark-v16-source.zip содержит проект vpnbench-next, не контроллер хакатона. 3. Методика Overall

Авторский относительный индекс эффективности

Overall = 100 × (Σ wj qj) / Σ wj

Для показателя «больше — лучше»: q = x / (x + b). Для «меньше — лучше»: q = b / (x + b). x — кандидат, b — результат контроля на той же серии. При x = b = 0 используем 0,5. Недоступные пары исключаются, их вес виден как недостающее покрытие.

50 — результат контрольного режима. Более 50 — преимущество по взвешенным критериям. Это не процент успешных миссий и не балл жюри.

Почему такой вес

60% отдано результативности, 20% — ресурсам, 10% — времени и 10% — отсутствию аварийного завершения. Суммарная энергия и удельный расход различаются: нельзя считать рост общего расхода экономией только потому, что спасено больше людей.

Число спасённых и M1 коррелируют, но здесь намеренно учитываются оба: макросреднее M1 не даёт крупным картам вытеснить маленькие, а число эвакуаций отражает фактический объём результата. Никаких баллов только за ML, NSGA-II, размер кода или графику.

Официальная формула ТЗ (§12.1)

TotalScore = 0,3 M1 + 0,2 M2 + 0,1(M3 + M4 + M5 + M6 + M7)

Официальный M1 = Σ(pk ck) / Σ pk; c отражает корректность с учётом полноты, сроков и безопасности. Новый бенчмарк измеряет бинарную эвакуацию при равных приоритетах. M2–M7 не оценены официально. Отсутствие такой оценки нельзя заполнить субъективными цифрами. Согласно §13.6, минимальная совместимость — необходимый допуск к победе; согласно §6.1.1 среда должна моделировать непрерывное 3D-пространство.

7. Как зафиксировать финальное решение

Конфигурация релиза: MetaRescue с нативным Net65 + переносимый Adaptive Survey. Сохранить возможность отката к greedy/Net65. Не переписывать Unreal-логику ради новых тестовых цифр.

  1. Сделать коммит текущей рабочей сборки. Наложить GlobalDispatch → Bottleneck → ResourcePredictor → AdaptiveSurvey строго через apply_patch.py (SHA-проверка). При отличающихся хешах — ручное точечное слияние, без принудительной перезаписи.
  2. Провести полный набор unit/HTTP/Unreal Automation и smoke-запуск того же нативного пресета. В текущей сессии прошли только 24 целевых теста четырёх патчей; полного регрессионного прогона и UE-сборки не было.
  3. Для переносимого профиля использовать --scout-patrol net65 --portable-dispatch adaptive-survey. Если профиль не поддерживает необходимые публичные возможности, действует предусмотренный в исходниках fallback; самостоятельную проверку нового неизвестного профиля не заменять предположением.
  4. Провести настоящую независимую двустороннюю приёмку на трёх новых seed с исправленной сторонней парой. Не засчитывать собственные 2D-профили и Atlas как полное закрытие M5.
  5. До физического сравнения не заявлять рост M1 в Unreal. На защите отделить исследовательскую эффективность (896 запусков) от готовности нативной среды.

Воспроизведение новой серии

В архиве доказательств лежат скрипты compare.py, compare_core.py, benchmark_core_compare.py, сырые результаты и логи. Из корня пропатченного MetaRescue скопировать compare*.py в корень, benchmark_core_compare.py — в experiments/mission_flow. Запустить:

python compare.py > common.jsonl
python compare_core.py > core.jsonl
python -m unittest tests.test_portable_flow tests.test_bottleneck tests.test_resource_predictor tests.test_adaptive_survey -v

Код генератора и физика не изменялись. p95 в таблице — среднее p95 по миссиям, измеренное на текущей машине; это не нативный FPS и не строгая сквозная задержка HTTP.
