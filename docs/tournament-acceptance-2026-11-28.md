## Нативные механизмы

На HTTP-границе снимки тела агента выражены в метрах. Для обычной карты
публичный объём суши включает высоту центра шасси. Физический движок отдельно
проверяет уклон, столкновения, допустимую среду движения и препятствия.
Для стандартного `move` из парковочного дока нативный исполнитель проходит
свои выездные точки через те же проверки безопасности. Переназначение движения
сохраняет ещё не пройденную часть выезда. Явные последовательности `follow_route`
исполняются в порядке, указанном контроллером.
Положение пункта помощи в публичном наблюдении соответствует доступной
площадке приёма. Центр связи хранится отдельно в модели среды.
Счётчик `safety_violations` увеличивается при фактическом контакте двух
машин, входе тела в активный запретный объём или выходе из допустимой
границы. Касания одной пары, повторяющиеся чаще четырёх раз в секунду,
составляют один контакт. Падение обломков учитывается собственными
физическими журналами. Предотвращённая опасность остаётся записью об отказе
или подтормаживании агента. На reset счётчик нового эпизода начинается с нуля.

Метка `carrier_id` появляется из реально погрузившего человека носителя.
Запрошенные действия не изменяют состояние цели. Среда связывает результат
с `decision_id`, индексом и ID команды, транспортом и физическим журналом.
Доля `mission_completion` основана на физически завершённых эвакуациях.
Остановка включает локальный аварийный тормоз среды. Это даёт возможность
удержать исполнителя при потере связи. Терминальный статус публикуется после
подтверждённой остановки подвижных агентов.

Повтор физического стенда Приложения А опубликовал восемь категорий агентов.
Подземный, надводный и подводный агенты завершили разрешённые маршруты
на 12-й модельной секунде. Их пройденные дистанции составили 11,70, 12,81
и 15,12 м. Пять недопустимых заявок на движение вернули `INVALID_COMMAND`
до изменения модельного времени. Свидетельства в
`core-acceptance/tournament-annex/verification.json`.

Два физических повтора одной ленты сошлись по восьми видам возмущений.
Поздняя цель появилась в публичных наблюдениях на 12,7 с в обоих опытах.
Максимум полученной глубины составил 0,41 м. Сохранены измерения по сухой
и грязной поверхности, повреждённой дороге, мелкой и глубокой воде.
Свидетельства в `core-acceptance/tournament-events/verification.json`.

Нативный тест разряда подтвердил отказ загруженного ровера на 31,8 с,
освобождение пострадавшего в его фактической позиции и повторное подтверждение
дроном на 33,4 с. Пятнадцать снимков подтвердили неизменность положения
человека после освобождения. Тест радиосвязи повторил 100% потерю пакетов,
публикацию offline и восстановление обмена. Свидетельства в
`core-acceptance/tournament-power-loss/verification.json` и
`core-acceptance/tournament-radio/verification.json`.

Автономный профиль с двумя NSGA-II и Global/Local в режиме MOCK сохранил
3 из 3 физических эвакуаций за 438,97 с при нуле нарушений безопасности.
Отчёт проверил использование обоих оптимизаторов, реальные погрузочные
фазы и передачу медпункту. Источник свидетельств —
`core-acceptance/tournament-workflow/verification.json`.

Во время доработки журналы последовательно показали стоянку дрона у точки
обзора, блокировку ровера направляющей дока и недоступную публичную точку

Оригинальный `pair --normalize --strict` на фиксированной City 2.2

(`0001b29`, `native-fixed-city-777-resumed/witness.json`). Для второго
испытания в отдельной копии карты изменён только `settings.seed`. Хэши
и проверка равенства остальных входов сохранены в
`core-static-r3-city22-seed777.fixed.manifest.json`. Обычный `reset` на
другой seed пересоздаёт карту, поэтому его исход измерен отдельно.

На сгенерированной карте seed 777 первый прогон достиг `time_limit` на
480 с с одним погруженным пострадавшим. При повторном вычислении из

Свидетельство — `recorded-generated-route-regression.json`.

В новом физическом прогоне `native-generated-budget/witness.json` на
`0001b29` носитель перевёз пострадавшего примерно на 139 м, после чего
физический исполнитель остановил движение у препятствия. При закрытии
эпизода миссия имела статус `time_limit` на 480 с, 0 из 3 эвакуаций и
0 зарегистрированных нарушений. Строгий допуск пройден. Участок
остановки виден в `core-runs/.../truth.records` этого опыта. Гарантия
достижения медпункта на каждом сгенерированном городе для переносимой
политики остаётся открытой.

У встроенных сценариев `coverage_search` и `coordination_reconfiguration`
есть общий исполнитель `executor`. Специализированный `rescuer` требует
способности двигаться и переносить груз. Параметр `priority_bias` входит
в объявленную схему. При увеличении значения добавляется задержка обработки
пропорционально `1 − priority` по публичной шкале [0, 1]. При приоритете 1
действует только задержка радиоканала. Эту зависимость проверяет
`MetaRescue.Core.TournamentPriorityDelay`.
Все движения и сервисы проходят штатную проверку доступности и возможностей.

Нормализованный RPC использует публичные наблюдения. Внутренний автономный
профиль сохраняет два NSGA-II, Net65, Counterfactual Value, опциональный CF
FullFleet Fast и Global/Local AI. RPC повторно использует общий геометрический
планировщик, протокол, определения действий и выбор по объявленным сценариям.
Его базовый запуск происходит без среды, ленты истины и внешней модели.
Нативная публикация `observe` сообщает допустимый параметр радиуса. При
необязательном радиусе используется радиус среды. При движении контроллер
учитывает реакцию позиции на цель. Для сканирования вблизи точки допустимое
отклонение применяется после проверки, что публичная позиция перестала меняться.
Агент подходит к обнаруженной другим участником цели в трёхмерном
пространстве. Перед выдачей манёвра проверяется путь по опубликованным зонам.
Наземный носитель без цели ожидает в доступной позиции, пока работает
доступный по связи воздушный разведчик с резервом энергии.
После подтверждённой погрузки носитель получает приоритет в общем бюджете
проверок маршрутов. Регрессия с одним доступным расчётом воспроизводит
прежнюю конкуренцию с фоновым поиском.

## Непрозрачные сценарии, действия и устаревшие форматы

В действующем вызове организатора контроллер получает только Observation.
Отдельный `GET /capabilities` выполняет оркестратор. В профиле C
Observation на старте содержит пустые `scenario_ids`, а само объявление
непрозрачного ID находится в capabilities. В D в Observation остались
непрозрачные имена действий без схем их семантики. Для их разрешения
реализована необязательная передача публичного `capabilities` вместе с
первым Observation эпизода. Схемы и соответствия фиксируются на эпизод.
Это предложение для согласования с организаторами. Судейский чекер
продолжает вызывать базовый интерфейс.

Для старых координат и ресурсов J предусмотрен явно включаемый
`--core-mode declared`. Он использует опубликованное преобразование.
Запуск strict на J остаётся отказом. Нормализатор, источники партнёров
и правила обязательной структуры сохранены.

| Atlas 0.2 → Unreal | 0/4 | POST `/v1/controller/decide`, HTTP 400, `INVALID_REQUEST`, `$.error.message` — «unknown endpoint». У замороженного контроллера Atlas отсутствует маршрут §2.2. |
| Metaroi v9 → Unreal | 0/4 | POST `/v1/environment/step`, HTTP 422, `INVALID_SCENARIO`. В `$.selected_configuration.parameters` v9 передал необъявленные `energy_reserve` и `search_spacing`. Листинг 5 и §1.10 Приложения А. |

У Lab метрика терминального состояния относится к доставке помощи в его
модели. В этих трассах зарегистрированы публичные переходы целей в delivered.

журнале Unreal и независимой модели A–K.
