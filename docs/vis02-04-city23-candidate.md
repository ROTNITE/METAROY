## Изоляция

Новые миры включают `settings.disaster_revision = 1` только с city 2.3.
Отсутствующее поле или 0 сохраняет старую сериализацию настроек, генерацию
и профиль `metarescue.urban-disasters.v1`. Новый приватный профиль объявлен
как `metarescue.urban-disasters.v2`; формат ленты остаётся events-3d.2.0.
Не заменять замороженные планы серий, старые карты и статистику. Новые
результаты хранить отдельно. Контроллер видит только доставленные наблюдения.

## Реализованный исходный код

- VIS02: после длительного горения целого/частично повреждённого многоэтажного
  дома возникает причинное событие collapse. Игровые задержки 110/85/65/55 с
  по variant 0/1/2/3 — не нормативный расчёт прочности. Повторный fire одного
  дома не дублирует тепловой отказ, уже разрушенные варианты 4/5 не создают
  искусственный верхний этаж. Не меняются первичные испытания вероятностей.
  Проверяются parent_id, source_object_id, время, длительность и клетки
  дочернего события в Python и C++. Периферийные fire-события нового профиля
  истекают одновременно с исходным пожаром. Используются исходные реальные
  владельцы деталей, существующий Chaos и удаление эффектов на исчезнувших
  проёмах. Это ограниченная игровая причинная модель, не расчёт материала.
- VIS03: интегрирование по настоящему расширяющемуся наклонному сечению,
  разбиение в точках входа/выхода и границах feather, 8-точечная квадратура.
  Одинаковая формула в C++ и HLSL, обрезка по opaque scene depth, режим
  камеры внутри объёма; у новой редакции убраны дополнительные дымовые
  спрайты с независимой непрозрачностью и фиксированный предел 650 м
  отображения физического объёма. Старый материал Revision5 не меняется.
  Новый Revision6 собирается из проверенной текстуры T_SmokeWisps R5
  (Kenney, CC0; происхождение в disaster-assets.md). Импорт не исполнялся.
- VIS04: каждые 0.5 модельной секунды консервативные 5 м клетки вычисляются
  из фактических коллизий крупных event-owned фрагментов и wreck, включая
  отдельные экземпляры ISM/HISM. Высокие обломки на крыше не блокируют улицу
  только по проекции. История используется для наблюдения освобождения
  клетки. Данные не обходят LOS, сенсорный шум и очередь доставки. Фикс
  фантомных фрагментов при неудачном удалении частей. Старые клетки риска
  сохраняются: обнаружение физического препятствия дополняет их, а не
  разрешает движение через горячую или нестабильную область.
- Город: в новой редакции единый процедурный рельеф улиц без наложенных
  ModularRoadSectionV1; наружные жилые и хозяйственные фасады получают окна,
  подоконники, двери, козырьки, кровельные детали и гаражные ставни.
  Существующие материалы, без новых внешних лицензий. Дальняя детализация
  ограничена, геометрия декоративная, батчируется и не добавляет коллизий.
  Размещение сигналов ограничено блоками 65 м вместо 88 м, пространственный
  индекс исключений, проверка конфликтов с другими подходами и полюсами.
  Переходы и стоп-линии — общая неколлизионная сетка на рельефе, которую
  вырезает существующий механизм повреждения дороги и восстанавливает reset.
  Потеря питания после локального повреждения моделируется осторожной
  фазой Dark. Реальное число сигналов и FPS надо измерить.

## Фактические независимые проверки (Linux, без Unreal)

1. `python -B -m unittest discover -s tests -v` в отдельной минимальной
   копии с **только** test_fire_failure.py — 5/5, не полный root-suite.
2. `g++ -std=c++17 -Wall -Wextra -Werror -O2 tools/smoke_optics_probe.cpp -o smoke_probe`
   и запуск — 500 случайных ветровых лучей + 6 аналитических/граничных
   случаев, максимальная ошибка пропускания 1.03919e-08, оптической толщины
   4.44876e-08. Содержимое локальных четырёх исходников/тестов сверено по
   Git blob SHA с веткой.
3. `python -B tools/smoke_shader_probe.py` — 1000 сравнений арифметики
   исходного HLSL после машинного перевода аннотаций и swizzle в C++;
   216 лучей изнутри AABB, 334 с обрезкой глубиной, включая координаты
   1500 м; максимальная ошибка непрозрачности 5.67404e-07.
   Это CPU-эмуляция формулы, не DXC, не компиляция материала, не кадры UE.

Ограничения среды: git clone не работает (DNS github.com); доступны
исходники через GitHub, но нет полного checkout/LFS, Unreal 5.8.4,
Windows toolchain и нативных кадров. Не утверждать, что весь репозиторий
прочитан, что новый C++ Editor module компилируется или что VIS закрыты.

## Приёмка на отдельной Windows-копии

Не запускать одновременно Unreal. Сохранить исходные C/D и старые архивы.
Получить LFS в candidate worktree. Создать baseline worktree на указанном SHA.
Из корня кандидата:

```powershell
python -B -X utf8 -m unittest discover -s tests -v
python -B -X utf8 tools/check_city23_regression.py --baseline-root "<baseline-worktree>" --full --output "D:/MetaRescue-output/vis23-regression-01.json"
python -B -X utf8 unreal/launch.py --quarter --build
python -B -X utf8 unreal/tools/run_disaster_art.py --kind smoke-v2 --inputs "<existing-disaster-input-manifest.json>" --output "D:/MetaRescue-output/smoke-v2-import-01"
python -B -X utf8 unreal/launch.py --automation MetaRescue
python -B -X utf8 tools/generate_city.py --city-revision 2.3 --disaster-revision 1 --size 25 --seed 2026 --output "D:/MetaRescue-output/vis23-world-01.private.json"
python -B -X utf8 tools/run_mission.py --layout "D:/MetaRescue-output/vis23-world-01.private.json" --controller-profile counterfactual_value --ai-mode OFF --visible --realtime --frame-profile --name vis23-visible-01
git diff --check
```

Команда регрессии сравнивает 271 старый/исходный случай (5 редакций × 9 размеров
× 3 seed × 2 профиля + максимальный конкурсный флот) и 55 новых v2 случаев.
Это запланированная матрица, а не выполненные 326 прогонов. Отдельно
test_disaster_v2.py проверяет совместные типы событий, маршрутизацию после
доставленных измерений и очищение, эти тесты ещё не запускались в полном checkout.
Для воспроизводимого сценария с событиями использовать settings JSON с
`city_revision: "2.3", disaster_revision: 1, event_profile: "v3", horizon: 480`
и 100% всех восьми вероятностей (отдельный нагрузочный fixture, не статистика
конкурсной серии). Не менять вероятности исходного плана.
