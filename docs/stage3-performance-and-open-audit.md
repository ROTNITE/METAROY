## Нативный следующий контроль

Для обычной интерактивной миссии, не зачётной производительности:

```powershell
python -B -X utf8 -m tools.run_product --render-profile economy --fps-cap 45
```

`balanced` использует масштаб рендера 75%, `economy` — 60%,
сниженные параметры освещения, отражений, теней и эффектов. Отключение
графических эффектов не должно становиться отключением физических
последствий; проверить на нативной сборке. Не менять seed, хэш карты,
временной шаг и конфигурацию физики ради FPS. Для сравнения без cap
использовать существующий `tools/run_mission.py --visible --realtime
--frame-profile` и тот же неизменённый набор аргументов/layout для
обоих прогонов. Условия прогрева, длительность и критерии V10/V3-V09
сохраняются. Выяснять bottleneck по Game/Draw/GPU, отдельно RAM/VRAM
и p95 кадра; повторить штатную и тяжёлую движущуюся сцену.
Официальные источники Epic:
[Scalability](https://dev.epicgames.com/documentation/unreal-engine/scalability-reference-for-unreal-engine),
[Stat Commands](https://dev.epicgames.com/documentation/unreal-engine/stat-commands-in-unreal-engine),
[Unreal Insights](https://dev.epicgames.com/documentation/unreal-engine/unreal-insights-in-unreal-engine).

## Разрешение противоречий в документации

В старых разделах handoff встречаются исторические 159/161 требований,
0/450 и более поздние 180/450. Они описывают разные даты, а не свежий
инвентарь. Сейчас в JSON 185 требований; ход локальной серии
и LIVE-счётчик определять только после проверки реальных манифестов и
ledger на машине владельца. Эта ветка не запускала новую нативную серию
и не записывала новые LIVE-вызовы. Синтетический HTTP-бенчмарк не меняет
число зачётных миссий. Нельзя считать pending реализационно отсутствующим
без отдельного изучения кода и нельзя считать partial проверенным.
